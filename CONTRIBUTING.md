# Contributing

Before contributing, confirm that you have permission to redistribute any code or data you add. Never commit raw sequencing reads, participant-level metadata, credentials, QIIME artifacts, archives, or generated result folders.

For a code change:

1. Explain the scientific or reproducibility reason for the change.
2. Update the README or documentation when behaviour, parameters, or outputs change.
3. Run the structural validation commands described in `docs/reproducibility.md`.
4. Record changed software versions and random seeds where relevant.
5. Keep upstream code changes isolated and clearly attributed.

Pull requests should state whether the change affects the biology workflow, ASV/OTU branch, metadata handling, feature selection, model evaluation, or reporting.
